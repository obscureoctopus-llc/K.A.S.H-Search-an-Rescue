# K.A.S.H-S.a.R.S
Search and Rescue System.

## CYD firmware

`cyd/src/main.cpp` replaces `PLATFORMIOIDE.txt`. The root PlatformIO project
builds only the CYD application, not the bundled Seeed/bridge sketches.
Use PlatformIO Core 6.1.18 from the repository root:

```sh
pio run -e cyd_esp32_2432s028r
pio run -e cyd_esp32_2432s028r -t upload
pio device monitor -b 115200
pio test -e native
```

Platform and libraries are pinned in `platformio.ini`. The application is
`.pio/build/cyd_esp32_2432s028r/firmware.bin`; use PlatformIO upload to flash
the application, bootloader, and partition table at the correct offsets.
`firmware/` contains legacy binaries with **unverified source/configuration
provenance**, not regenerated by this build. Do not assume they contain these
fixes or flash an application-only binary at address zero.

### Wiring and calibration

Target: **ESP32-2432S028R resistive-touch CYD, ILI9341**, 240×320 pixels,
landscape rotation 1 (320×240). Other panel revisions require verification
of their driver and pinout.

| Function | ESP32 GPIO |
| --- | --- |
| TFT MISO / MOSI / SCLK | 12 / 13 / 14 |
| TFT CS / DC / reset | 15 / 2 / -1 (no software reset pin) |
| Backlight | 21, active high |
| XPT2046 touch SCLK / MISO / MOSI / CS | 25 / 39 / 32 / 33 |
| Telemetry UART RX / TX | 16 / 17 |

The TFT uses the default HSPI bus in TFT_eSPI; touch uses a separate VSPI bus
through XPT2046_Touchscreen, polled without an IRQ pin. TFT_eSPI's shared-bus
touch support is intentionally disabled.

Connect the sender's **3.3 V UART TX** to GPIO16 and share a real ground.
GPIO17 is optional (the display sends no commands). UART is **115200, 8N1**.
Do not connect RS-232/5 V signals directly or power/ground modules via GPIOs.
Supply the CYD through its documented power input.

`cyd/include/sonar.h` retains legacy calibration `{287, 3450, 483, 3314, 1}`:
X offset/span, Y offset/span, TFT_eSPI swap/inversion flags. This is not a
universal factory calibration. The conversion accounts for XPT2046's raw
axis ordering at rotation 1. Verify it on the actual panel: if touch is
misaligned, measure raw corner values with XPT2046_Touchscreen's examples
and update the offsets/spans/flags. Values must have nonzero spans.

### Telemetry contract

Only ASCII frames with exactly six unsigned decimal fields and LF termination
(optional CR before LF) are accepted:

```text
R,status,moving_cm,moving_energy,static_energy,static_cm,detection_cm
R,1,250,50,0,0,250
R,2,0,0,40,100,100
R,0,0,0,0,0,0
```

Assumptions: LD2410-style status 0=none, 1=moving, 2=stationary, 3=both;
distances 0–1200 cm; energy 0–100. The previously ignored fifth numeric
field is assumed to be stationary distance and is now validated. These are
the **CYD adapter contract**, not a verified protocol for every sensor here.
A sender must convert its sensor protocol to this format. Legacy CSV has no
checksum; validation cannot detect all plausible corruption.

The bundled `A-Breath-Away-main/A-Breath-Away-main/src/main.cpp` emits
`K.A.S.H CROWPANEL|state=...|raw=...`; `seedstudio/seedstudio.ino` is a LoRa
AT-command test. Neither supplies compatible range frames. Binary LD2410/MR60
packets and LoRa `+RCV` wrappers are not accepted. 60G mode is a **raw-byte hex
viewer**, not a decoded 60 GHz radar display. UI switching does not switch the
physical sensor or baud rate.

Parsing is nonblocking, with a 63-byte maximum line. Overflow, embedded NUL,
and inter-byte gaps >500 ms discard the line through LF. Invalid/incomplete
frames never refresh freshness. All metrics/targets clear when the last valid
complete frame is **more than 500 ms old**, including across `millis()` rollover.
Mode changes clear telemetry, partial input, queued UART bytes, and console
position.

Range-only telemetry has **no bearing**. A single marker is drawn on the
centerline, never at the decorative sweep angle. It does not represent
direction or multiple people. Distances ≤15 cm are not plotted; the 500 cm
display scale clamps longer ranges while metrics retain the reported distance.
Markers decay without new frames; no-target frames clear them immediately.
Red indicates zero moving energy and stationary energy >10 (legacy heuristic),
**not evidence of entrapment or a life-safety classification**.

The 320×170 radar viewport is rebuilt in an 8-bit sprite (~54 KB) every 20 ms
and pushed below the controls, removing previous beam/marker pixels even at
sweep reversals. Buffer allocation failure displays an error instead of using
an invalid buffer.

### Tests and hardware bring-up

Native tests cover corrupt/incomplete/overlong frames, numeric bounds,
timeouts/rollover, idle rendering, coordinate/calibration math, sweep reversals,
and 24G↔60G transitions. The packet-to-framebuffer integration test feeds the
example packets through the production parser/state/renderer, checking marker
position/color and removal of stale pixels on a software canvas.

The same tests can run with an installed C++ compiler:

```sh
g++ -std=c++11 -Wall -Wextra -Werror -I cyd/include \
  cyd/test/test_sonar/test_main.cpp -o /tmp/cyd-tests
/tmp/cyd-tests
```

Tests do not verify electrical wiring, SPI timing, touch calibration, or driver
compatibility. On the board, first run TFT_eSPI's solid-color/display examples
with this pinout: red, green, blue, and black must fill the **entire** panel.
Persistent half-screen static without telemetry needs panel/driver/power/SPI
diagnosis (try a lower SPI clock after checking the board revision). Then send
the example packets to GPIO16: expect one centerline marker, no beam trails,
and `NO TELEMETRY` after >500 ms without a complete valid frame. Verify mode
switching on-device before field use. No hardware validation or search-and-rescue
certification is implied by software tests.
